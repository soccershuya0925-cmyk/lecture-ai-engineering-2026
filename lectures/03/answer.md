## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回の `app.ask` は、6回とも「難易度の3段階で、まずレベル1から」と答え、正しい意味にならなかった。エージェントは先に `search_glossary('3レベル')` で用語集を引き、「基礎・実装・発展のどれか1つに取り組めば完了・原則として採点しない」と正しく答えた。最後に「関連する回：第1回」も付いた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」では `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。用語を1つずつ分けて検索していた。
- 1つの質問での LLM 呼び出し回数（`requests`）：2（ツールを呼ぶ回と、結果を見て答える回）。ツールを2つ呼んでも requests は2のままで、2つのツール呼び出しは1回の応答の中でまとめて出ていた。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)`。説明は「指定した回の用語から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』『復習のクイズを出して』のように、確認問題・小テスト・クイズを求められたときに使う。question を出題し、answer は利用者が答えるまで見せない。」。その回の用語が無いとき（第0回など）は、用語がある回の一覧を返す。`--trace "第2回の内容から確認問題を1問出して"` で `make_quiz({'lecture': 2})` が呼ばれ、「QLoRA」の問題が答えを伏せた形で出た。`uv run pytest -q` は 11 passed。

- 気づき・疑問：
  - A：「必ず検索する」の行を消しても、6回とも検索してから答えた。`search_glossary` の docstring にも「答える前に使うこと」と書いてあるので、ツールの説明文だけで呼ばれていたと考えた。指示を消して減ったのは入力トークン（約48）だけだった。
  - B：「まとめて入れる」にすると、検索は2回から1回になり、入力トークンは1434から1129に減った（約21%）。今回は検索の関数が部分一致で両方の用語を拾うので答えは崩れなかった。もし検索が完全一致だけだったら、何も見つからなくなっていたはず。docstring の書き方は、ツールの中身（検索の仕組み）と合わせて決める必要がある。
  - C：確認問題は、質問と関係のない第1回から出た。trace を見ると、make_quiz は search_glossary と同じ1回目の応答の中で呼ばれていて、LoRA が第2回だという検索結果を見る前に回を決めていた。ツールの呼び出しがまとめて出るので、前の結果を使ってほしいツールは、指示に「検索の結果で分かった回で make_quiz を呼ぶ」と順番を書く必要がありそう。まだ試していない。

  - 疑問：flash-lite では指示を消しても検索したが、ほかのモデル（flash）でも docstring だけで同じように検索するのか。
